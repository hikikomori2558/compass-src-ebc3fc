# frontend_patient — PWA-дневник пациента (контур Условия 2)

Мобильный PWA без фреймворков и без сборки: привязка к лечащему врачу по одноразовому
QR и ежедневный чек-ин, который уходит **напрямую врачу** — без мессенджеров и третьих
лиц (152-ФЗ; ИДС-согласия создаются в момент привязки на бэкенде).

## Запуск (стенд разработки)

```bash
# из корня репозитория
python3 -m http.server 5501 -d frontend_patient
# бэкенд (для привязки и чек-инов):
python3 -m backend.main          # + docker compose up -d (БД обязательна для auth/checkin)
```

PWA: `http://127.0.0.1:5501/` → «Установить на экран» (iOS 16.4+ / Android).

## Поток пациента

1. Врач в АРМ (`frontend_doctor/`, раздел «Мониторинг и Связь») нажимает
   «Привязать пациента по QR» → `POST /api/v1/auth/invite` (TTL 24 ч, одноразовый).
2. Пациент сканирует QR → открывается эта страница с `?token=...` →
   `POST /api/v1/auth/bind` → пациентский JWT, согласия зафиксированы.
3. Ежедневный чек-ин → `POST /api/v1/patient/checkin`
   (идемпотентный `event_uuid`; при критичных ответах — экстренный алерт врачу
   по WebSocket, в канале только пустой пинг).
4. Нет сети — чек-ин встаёт в локальную очередь и уходит при восстановлении связи.

## Что здесь принципиально НЕ делается

- **Никаких советов и решений пациенту** (Условие 3): только фиксация и передача врачу.
- Пропуск вопроса о суицидальном риске не считается «нулём»: сервер честно помечает
  `suicide_item_missing`, PWA переспрашивает, врач видит «риск не оценён».
- Service worker кэширует только оболочку; клинический обмен — всегда сеть.
