# Как пушить в репозиторий: инструкция для Михаила (терминал + VS Code)

Репозиторий: `https://github.com/hikikomori2558/rapira-clinical-compass` (private, ветка `main`).
Локальная копия: `~/rapira-clinical-compass`. **Работаем только внутри неё** — никаких вложенных папок со своим `.git`.

---

## 0. Куда что класть (главное правило)

| Что сделал | Куда положить |
|---|---|
| C-код: новые/изменённые `.c`, `.h` | `c_core/` |
| Клинические JSON: шкалы, ОХЛП, коридоры РКИ, корпус виньеток | `clinical_data/` |
| Python-модули биоконтура: движки, мост ctypes, FastAPI-роутер | `backend/` |
| Бенчмарки, метрики, протокол апробации, скрипты генерации графиков | `benchmarks/` |
| Сгенерированные графики PNG/SVG | `benchmarks/plots/` (скрипт кладёт туда сам) |
| Документация, объяснения, статьи | `docs/` |

**Нельзя коммитить** (и не нужно — уже в `.gitignore`): `*.so`, `*.dylib`, `.venv/`, `__pycache__/`, `.DS_Store`, `.env`.
Скомпилированный `libcompass_core.so` каждый собирает локально через `python3 scripts/build_c_core.py`.

**Нельзя создавать** новые папки верхнего уровня и вложенные git-репозитории — новые модули кладутся прямо в канонические папки из таблицы.

## 1. Терминал: полный цикл

```bash
cd ~/rapira-clinical-compass

# ШАГ 1. Всегда сначала забрать свежее (пока ты спал/работал, напарник мог запушить)
git pull --rebase origin main

# ШАГ 2. Посмотреть, что изменилось
git status                # красное — изменено/новое, зелёное — подготовлено к коммиту
git diff                  # показать сами изменения (q — выход)

# ШАГ 3. Добавить ТОЛЬКО свои файлы/папки (по пути, а не git add . )
git add c_core/ backend/ clinical_data/ benchmarks/

# ШАГ 4. Коммит с понятным сообщением
git commit -m "feat(c_core): ускорил RK4-решатель и поправил Чайлд-Пью"

# ШАГ 5. Отправить на GitHub
git push origin main
```

### Если `git push` отверг («rejected / non-fast-forward»)

Значит, напарник запушил раньше тебя. Нормальная ситуация:

```bash
git pull --rebase origin main    # твои коммиты встанут поверх его
git push origin main
```

Если rebase остановился с конфликтом (редко — вы работаете в разных папках):

```bash
git status                       # покажет файлы с конфликтом (both modified)
# открыть файл, найти строки между  <<<<<<<  и  >>>>>>>
# оставить правильный вариант, маркеры <<<<<<< ======= >>>>>>> удалить
git add <файл>
git rebase --continue
git push origin main
```

Отменить неудачный rebase: `git rebase --abort` — вернёшься к состоянию до него.

### Полезные команды на каждый день

```bash
git log --oneline -10            # последние 10 коммитов
git restore путь/к/файлу         # откатить НЕЗакоммиченные изменения в файле
git stash                        # спрятать незакоммиченную работу (перед pull)
git stash pop                    # вернуть спрятанное обратно
git checkout -                   # вернуться в предыдущую папку
```

## 2. VS Code

1. **Открывай именно корень репозитория**: File -> Open Folder -> `rapira-clinical-compass` (не вложенную папку!).
2. **Забрать свежее перед работой**: `Cmd+Shift+P` -> `Tasks: Run Task` -> **«2. Синхронизировать с GitHub»** (это `git pull --rebase`), либо иконка Source Control (`Ctrl+Shift+G`) -> кнопка `...` -> Pull.
3. **Закоммитить и запушить через UI**:
   - В панели Source Control видно все изменённые файлы. Наведи на файл — `+` (это `git add`).
   - В поле внизу напиши сообщение коммита -> кнопка **Commit**.
   - Затем кнопка **Sync Changes** (или `...` -> Push) — отправит на GitHub.
4. **Собрать и проверить перед пушем** (`Cmd+Shift+P` -> `Tasks: Run Task`):

| Задача | Что делает |
|---|---|
| 1. Собрать C-Core | компилирует `c_core/*.c` -> `libcompass_core.so` |
| 3. Проверить C-Core (Smoke Test) | бенчмарк отклика ядра, Метрика №1 |
| 4. Тест 3 эталонных сценариев | прогон демо-сценариев из презентации |
| 5. Бенчмарк 100 ЭМК | корпус + метрики + протокол апробации |
| 6. Научные графики | перегенерация `benchmarks/plots/` |
| 7. bio API сервер | Swagger на http://127.0.0.1:8000/docs |

`Cmd+Shift+B` (macOS) / `Ctrl+Shift+B` — быстрый запуск задачи №1 (сборка).

5. **Terminal в VS Code**: `Ctrl+` ` (обратная кавычка) — откроется прямо в папке репозитория, дальше команды из раздела 1.

### GitHub Desktop (альтернатива, если привычнее)

- `Fetch origin` перед работой, `Pull origin`.
- Слева отмечаешь изменённые файлы галочками, внизу Summary + описание -> **Commit to main** -> сверху **Push origin**.
- Пуш отклонён — сначала `Repository -> Pull` (rebase), затем снова Push.

## 3. Правила, чтобы не ловить конфликты

1. **Pull --rebase перед началом работы** — железно, каждый раз.
2. **Пуш малыми партиями**: закончил кусок (раз в 1–2 часа) — коммит + push. Чем свежее коммиты, тем меньше пересечений.
3. **Не трогай чужие зоны**: Всеволод — `micro_nets/`, `frontend_*`, основной `backend/`, `c_core/pii_scrubber.c`, `c_core/simd_lexer.c`. Михаил — всё остальное из таблицы раздела 0.
4. **Генерируемые файлы коммитим осознанно**: корпус виньеток детерминирован (seed=2026) и не меняется между прогонами; протокол `PROTOCOL_APROBATION_2026.md` и графики меняются (тайминги) — коммить их, когда хочешь зафиксировать результат для презентации.
5. Сомневаешься, что файл попал куда-то не туда — `git status` покажет путь; сверься с таблицей раздела 0.

## 4. Формат сообщений коммитов (коротко)

```
<тип>(<зона>): <что сделал>
```

Типы: `feat` (новое), `fix` (исправление), `docs` (документация), `bench` (бенчмарки/графики), `refactor`, `chore`.
Зоны: `c_core`, `backend`, `clinical_data`, `benchmarks`, `docs`.

Примеры:

```
feat(c_core): добавил расчёт QTc-запаса в compass_core.c
fix(backend): hot-reload шкал не терял лицензию при перезагрузке
bench(benchmarks): перегенерировал протокол апробации после оптимизации
docs: добавил описание кластера К6 в BIO_CONTOUR_v26.md
```

## 5. Если что-то пошло совсем не так

```bash
git status                       # сначала всегда сюда — Git обычно сам подсказывает команду
```

- Закоммитил лишний файл -> `git rm --cached файл && git commit --amend --no-edit && git push --force-with-lease` (force — только на СВОЙ свежезапушенный коммит и предупредив напарника).
- Удалил файл по ошибке до коммита -> `git restore файл`.
- Репозиторий в странном состоянии -> напиши Всеволоду, НЕ делай `git push --force` в общую ветку молча.
