## 3. «Что будет оцениваться» — 6 критериев

1. **Научная обоснованность** — docs/SOURCES.md: 31 источник ([✓]/[~]), клик по цифре → `/sources?ref=`, 17 в guideline_sources; каждый факт в UI несёт evidence-строку.
2. **Клиническая применимость** — 3-кликовое правило; работает поверх ЭМК вендора без её изменения; пороги/точки контроля по КР (0/2/4/8 нед).
3. **Удобство интерфейса** — PWA: чек-ин 3 тапа, Duolingo-механика; врач: светофор + зоны; Playwright-прогоны без ошибок.
4. **Обязательные условия** — см. таблицу выше (10/10).
5. **Каждый пункт «что делает инструмент»** — см. таблицу выше (8/8).
6. **Апробация** — боевой тест БД (5 пациентов × 3 чек-ина + v7-блок, 30+ проверок), Playwright-прогоны двух интерфейсов, нагрузочный профиль, учения восстановления БД; все данные синтетические (сгенерированы сидами), ПДн отсутствуют по построению.

## 5. Известные ограничения (честно, чтобы не нашёл жюри)
- 16/105 «пациентов» без кластер-профиля — нет ни одной шкалы: честный 404 «нет данных» (не выдумываем).
- Источники [~] (ПРИВ n=170, ВАШ-сонливость) — из доклада организаторов, оригинал не открывался; помечены и в UI не фигурируют как [✓].
- Голосовые оси 14–15 — experimental, НАБЛЮДЕНИЕ вне клинических решений (П1 реестра, DAM обучена на английской речи) — подписано в коде и UI.
- Напоминания PWA — локальные слоты при открытой вкладке + periodicSync (push-сервер не используется, чтобы не зависеть от сторонних сервисов).
- Демо-стенд: 1 воркер uvicorn; для прод-профиля — `--workers N` (метрика 6 подписана честно).
