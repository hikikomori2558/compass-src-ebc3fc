# План апгрейда COMPASS v7 (кластеры → шкалы → остальное)

База: существующие 30% (PWA v6, сайдбар 3 вкладки, cluster_24d_analysis, RK45 what-if, cohort 7 персон). Решения: шкалы = GAD-7 (Г2 КР) + HADS-14 (самоотчёт) + HAM-A-14 (врач), PHQ-9 → HADS-D; кластер-карта = реальные пациенты + помеченные РКИ-референсы; порядок = кластеры → шкалы → остальное. После каждого этапа: деплой, Proвгon, коммит.

---

## Этап 1. Интерактивная кластер-карта (Obsidian-style) — визуально главное

**БД-миграция** (schema.sql + ALTER на боевой БД):
- таблица `patient_cluster_profiles`: patient_hash_id uuid PK→vault, z24 jsonb, cluster_code text, projection_x/y float, dtw float, ood jsonb, computed_at timestamptz; RLS как у patient_scale_assessments.

**Бэкенд**:
1. `backend/domain/routing.py` / pipeline: при analyze-and-route привязанного пациента сохранять `state_vector_24d` + `illustrative_2d_projection` + cluster_code + DTW в patient_cluster_profiles (UPSERT).
2. Скрипт `scripts/backfill_cluster_profiles.py`: для всех привязанных пациентов строит z24 **из реальных строк БД** — история patient_scale_assessments (GAD-7/PHQ-9/C-SSRS), medication_adherence_logs (приверженность, intake_time), therapy_day от bound_at → build_24d_state_vector → assign_cluster → **evaluate_mahalanobis_ood (реальный вызов C-ядра)** + параметры эллипса из fit_cluster_ledoit_wolf (ковариация кластера, Ledoit-Wolf).
3. Эндпоинт `GET /api/v1/compass-bio/cluster-map`: {clusters: K1–K5 (мета + umap_coords + эллипс от Ledoit-Wolf), patients: [{hash6, x, y, cluster, ood, dtw, gad7_delta}], reference_points: РКИ-референсы с флагом "reference": true (детерминированные сиды на сервере, помечены «референсные траектории исследований»), corridors}.
4. `GET /cluster-map/patient/{hash}`: z24 → **feature_contributions_to_d2** (топ-оси Махаланобиса по-русски), 6 ближайших соседей — реальные расстояния Махаланобиса между векторами пациентов внутри кластера.

**Фронт** (sidebar.js + compass.css): полная замена `drawClusterMap`:
- canvas pan (drag фоном), zoom (колесо 0.5–4x), drag узлов-пациентов, hover-тултип (hash, кластер, ΔGAD-7), клик узла → карточка (таймлайн + вклад осей + OOD-баннер «система не экстраполирует»);
- эллипс Махаланобиса — из серверных параметров ковариации (не хардкод); легенда честная: «референсные точки — траектории исследований, не пациенты»;
- удаление `CLUSTER_BLOBS`/seed 77 из фронтенда.

**Верификация**: клик «История» из когорты + карта показывает этого пациента; OOD-флаг у семени B (критический эпизод); 0 JS-ошибок.

## Этап 2. Шкалы строго по МЗ РФ

1. `backend/domain/scales_mz.py`: добавить item-определения:
   - **GAD-7** — официальные формулировки Приложения Г2 КР ГТР-2021 (заменить текущие смягчённые), пороги 5/10/15;
   - **HADS-14** — официальный текст 14 пунктов из Приложения Г1 КР МЗ РФ (подтверждён по КонсультантПлюс), подшкалы A/D, обратные пункты (4A, 1D, 2D, 7D), пороги 0–7/8–10/11–21;
   - **HAMA-14** — 14 пунктов 0–4 для врача (1–6 психическая, 7–13 соматическая, 14 поведение при осмотре — двухфакторная структура со слайда 2 доклада);
   - **CGI-S/CGI-I** — одна страница.
   Регистрация в scale_versions; каждая item-определение несёт `tip` («что спрашиваем — почему важно — что делать»).
2. **PWA**: survey.js переключается на `GET /scales/{code}` (item-level API уже есть — сервер = источник правды, правки текстов без релиза). Цепочки: «Опросник недели» = GAD-7 (Г2); «Шкала настроения» = HADS-14 (поочерёдно); PHQ-9 удалён, его п.9 заменён каскадом SAFETY (остаётся). Подпись «Шкалы по КР МЗ РФ (ГТР, 2021): скрининг Г2; тяжесть — HAM-A врача».
3. **Сайдбар**: вкладка «Пациент» → блок **HAM-A-14** (чипы 0–4 по пунктам, автосумма, разбивка психическая/соматическая), линии ответа ≥50% и ремиссии ≤7 на графике динамики 0/2/4/8 недель (КР).
4. БД: HADS/HAMA пишутся в patient_scale_assessments (scale_code в реестре), delta_prev автоподсчёт.

## Этап 3. Побочки/вопросы: объяснения в момент возникновения (до 100%)

1. Tips ко **каждому** item GAD-7 (7) и HADS (14) — в item-определениях сервера (Этап 2), формат «почему спрашиваем → что означает выраженность → что делать»; hot-reload шкал (Метрика №10) подхватывает правки без релиза.
2. **Побочки → adverse_events_and_risks** (таблица уже есть, не используется): при выборе симптома в дневнике PWA пишет запись НЯ (чип → MedDRA-название, severity, связь с приёмом) через новый `POST /adverse-events` (patient, RLS); врач видит список НЯ пациента в дашборде + кнопка «черновик извещения 1071» (route уже есть в routing.py).
3. Формулировки вопросов проверены по официальным текстам (Г2/Г1) — не «смягчённые пересказы».
