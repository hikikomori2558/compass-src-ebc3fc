# Редизайн интерфейса врача COMPASS: ресёрч → диагноз → новая информационная архитектура → реализация

**Проблема (ваша формулировка, подтверждена инвентаризацией):** сайдбар перегружен инженерными блоками (SLA p95/p99, PK 168ч, what-if, микросети, SHAP, CBR, провенанс-паспорт — 10 из 16 секций панели это технология, а не клиника) и при этом полезной клинической информации мало: врач не видит «что изменилось у пациента с прошлого раза», не видит свод «принимает/жалобы/динамика» на одном экране, падает в ступор. Внешне — «ИИ-дашборд»: плитки-близнецы, разнобой виджетов.

**Решение-рамка (согласовано):** инженерия → отдельная вкладка «Система» (для жюри), рабочие вкладки врача — «Пациент», «Когорта», «Сообщения»; визуальный язык — «медицинская записка» (Epic/UpToDate-стиль: белая записка, тонкие линейки, крупная цифра, светофор только по смыслу).

### R1. США — медстартапы и живые отзывы врачей
Источники (все с реальными голосами врачей):

- KLAS-сравнения: [Suki vs DAX vs Abridge vs Freed](https://intuitionlabs.ai), [glass.health ranking](https://glass.health/resources/best-ai-medical-scribe), [lucashealth](https://lucashealth.ai);
- Исследования: [Olson 2025 PMC (Abridge, 312 цит.)](https://pmc.ncbi.nlm.nih.gov/articles/PMC12492056), [Shah 2025 PubMed](https://pubmed.ncbi.nlm.nih.gov/39657021), наш уже верифицированный [Rotenstein JAMA 2026 (−16 мин/день)](https://jamanetwork.com).

**Что извлечь (шаблон):** (a) что врач хвалит = паттерн (пример из ресёрча: «меньше печатать, больше смотреть на пациента» → главный экран = пациент, не система); (b) что ругают = анти-паттерн («flowery-абзацы, требующие вычитки» → у нас: никаких сгенерированных «резюме» без ссылки на данные; «не отвечают на клинические вопросы» → каждый блок обязан отвечать «что мне с этим делать»); (c) структура первого экрана у лидеров.

### R3. Научная литература по интерфейсам
- [NN/g — Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure): вторичные детали — за клик, не на глазах; [NN/g — Dashboards/preattentive](https://www.nngroup.com/articles/dashboards-preattentive): операционный дашборд ≠ аналитический; цвет/размер/положение работают ДО сознания.
- [Olakotan 2025 PMC — usability EHR](https://pmc.ncbi.nlm.nih.gov/articles/PMC12206486) (152 цит.): данные логичными группами, прогрессивное раскрытие, критичное — подсвечено; [Cahill 2025 PMC](https://pmc.ncbi.nlm.nih.gov/articles/PMC11705737).
- Алерт-фатиг: [AHRQ PSNet primer](https://psnet.ahrq.gov/primer/alert-fatigue), [Blecker 2019 JMIR — interruptive vs noninterruptive](https://humanfactors.jmir.org/2019/2/e12469), [Fallon 2024](https://pmc.ncbi.nlm.nih.gov/articles/PMC10830237): алерты — только те, что требуют ДЕЙСТВИЯ; остальное — пассивные бейджи.
- Шкалы оценки: SUS (10 пунктов) + «time-to-first-insight» как наша метрика редизайна.

### R4. Дизайн-статьи и анти-ИИ
- Прошлые итерации (обязательно учесть): UX_UI_DESIGN.md §7 уже фиксирует «спокойный» язык — белый фон #fff, текст #16242f, бирюза #007d79 ТОЛЬКО акцент, светофор #1f8a4c/#b7791f/#c0392b только по смыслу, скругления 14/10px, «никакой красоты, затеняющей данные». Причина текущего провала — не палитра, а ИНФОРМАЦИОННАЯ АРХИТЕКТУРА (плитки-виджеты вместо записки).
- Анти-ИИ-чеклист (из прошлых детектов): ❌ сетка одинаковых карточек-плиток; ❌ иконка+цифра+спарклайн в каждом квадрате; ❌ тёмная тема с неоном; ❌ эмодзи-иконки; ❌ «AI-резюме» абзацами. ✅ линейка-разделители как в бумажной карте; ✅ один герой-блок; ✅ числа крупные с подписью-источником; ✅ типографика доминирует над декором.

## ФАЗА W — новая информационная архитектура (реализация, дни 2–3)

### W1. Вкладки врача (панель 440px и дашборд — одна IA):
- **«Пациент»** (главная): (1) герой-блок «Вердикт» — светофор + решение одной строкой + «что требуется от вас» (подтверждения/алерты, единственное место с красным); (2) «Что изменилось с прошлого визита» — ΔGAD-7/ΔHADS стрелкой + даты точек, новые жалобы/НЯ за период, приёмы/стрик — плотной запиской списком, НЕ плитками; (3) «Динамика» — один график GAD-7 с линиями КР (ответ/ремиссия); (4) «Действия» — 057/у-04, QR, сообщение, черновик 1071 (только те, что уместны).
- **«Когорта»** — текущая таблица 105 (оставить как есть: она уже работает, ярлыки/кластеры/OOD/поиск).
- **«Сообщения»** — треды по пациентам (сейчас спрятано в дашборде).
- **«Система»** (жюри/разраб): PK/what-if, кластер-карта 24D, SHAP, CBR, микросети, SLA, провенанс-паспорт, /sources. Подпись «технологический контур — врачу в приёме не нужен».
- Дашборд (развёрнутый) = та же IA шире; герой-блок крупнее; карта кластеров остаётся на «Системе» + мини-версия по клику «показать на карте» из «Пациента».

### W2. Визуальный язык «медицинская записка»:
- Карточки-плитки → одна белая записка с секциями, разделёнными линейками 1px #e4e7eb (как Epic); заголовки секций малые капсом 11px #6b7280; ключевая цифра 28px 700; текст 13px/1.55.
- Светофор = цвет строки-заголовка вердикта + тонкая левая полоса 4px, остальное — чёрно-белое.
- Кнопки — текстовые действия со стрелкой «→», вторичные — аутлайн; никаких иконок-эмодзи; максимум 3 иконки (колокольчик, ⤢, ✕).
- Бейджи ОБЯЗАТЕЛЬНО/ЖЕЛАТЕЛЬНО сохранить (уже различимы) — это семантика, не декор.

### W3. Реализация (файлы):
1. sidebar.html: новая IA — 4 вкладки врача + «Система»; перенос существующих блоков (код переиспользуем: drawWhatIf, drawClusterMap, loadCohortTable, HAM-A, 1071 — рендер остаётся, меняется место).
2. sidebar.js: вкладка «Пациент» собирает: вердикт (lastResult) + Δ-динамика (timeline API уже есть) + жалобы (adverse_events + diary) + действия; вкладка «Система» — существующие рендеры PK/mn/cluster/xai/cbr/sla/provenance почти без правок.
3. compass.css: записочная типографика (новые классы .note, .note-sec, .hero-verdict), удалить плиточный стиль дашборда.
4. Демо-лендинг и скриншоты обновить после перестройки.

### W4. Верификация (день 3):
- 3-клик прогон каждого сценария из UX_UI_DESIGN §2 (фиксируем фактические клики);
- SUS-опросник на 3–5 холодных открывателях (сами + 2 не-разработчика), цель ≥ 80;
- Playwright: 0 JS-ошибок, все сценарии кликами, скриншоты до/после в WALKTHROUGH;
- Анти-ИИ-детект: чеклист R4 по финальным скриншотам (плитки/неон/эмодзи = fail);
- Боевой тест БД — без регрессий (UI не трогает API, но прогнать).
