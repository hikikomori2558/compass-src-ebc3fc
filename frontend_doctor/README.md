# frontend_doctor — АРМ врача (OpenMRS 3 / IBM Carbon / CDS Hooks)

Рабочее место врача: SOAP-заметка с NER-разметкой ЭМК, CPOE с пересчётом DDI,
психометрические шкалы, Демпстер—Шефер по голосу, маршрутизация к психиатру
(ОБЯЗАТЕЛЬНО / ЖЕЛАТЕЛЬНО / ПЛАНОВОЕ), WS-канал критических алертов.

## Запуск

```bash
# из корня репозитория
python3 -m http.server 5500 -d frontend_doctor
python3 -m backend.main                     # API + C11-ядро (для полного режима)
docker compose up -d                        # БД (обязательна для входа и алертов)
python3 -m backend.db.seed                  # демо-доступы
```

Открыть `http://127.0.0.1:5500/`. Вход: `neuro.ivlanov` / `compass-demo-2026`
(после seed; пароль демонстрационный). Без входа доступен режим офлайн-фоллбэка.

## Источник клинических значений

Приоритет — C11-бэкенд: `POST /api/v1/cdss/evaluate-encounter` считает RK45(5)4
фармакокинетику, Bitap-NER ЭМК, Демпстера—Шефера и точные значения Оуэна в C.
Бейдж в шапке всегда показывает источник: **C11-СЕРВЕР** или **ЛОКАЛЬНЫЙ
ФОЛЛБЭК** (браузерная аппроксимация для демо без сервера; она не притворяется C11).

## Почему без тулчейна (сознательное решение)

Vanilla JS без сборки и внешних зависимостей, стили IBM Carbon с CDN — как
фронтенд OpenMRS 3 собирается из независимых модулей. Для стенда чемпионата это
означает: нет `npm install`, нет node на Debian-ноде демо, обновление = rsync.
Логика разделена: `clinical_engines_client.js` (связь с API + движки + canvas) и
`app.js` (состояние карты и рендер). Свои canvas-графики вместо chart-библиотек —
нулевые зависимости и полный контроль отрисовки клинических коридоров.
